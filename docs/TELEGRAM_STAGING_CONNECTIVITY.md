# Telegram: проверка реального подключения без запуска бота

**Назначение:** убрать неопределённость между «тесты проходят» и «Telegram принимает токен». Команда ничего не публикует, не отправляет сообщения, не считывает входящие сообщения, не изменяет webhook и не запускает бота.

## Что уже можно проверить

Из корня репозитория в локальном Python-окружении:

```bash
python -m pip install -r requirements.txt
python -m app.telegram_staging_probe
```

Вторая команда запускает **локальную**, не сетевую проверку наличия TELEGRAM_BOT_TOKEN; она не показывает его значение. Параметр `polling_preflight_passed` закономерно равен `false`, так как доступа к Telegram не было.

При наличии **отдельного тестового** токена от @BotFather (хранить только в .env, не передавать в чат или GitHub):

```bash
python -m app.telegram_staging_probe --online
```

Проверка использует лишь два **read-only** Telegram Bot API вызова: `getMe` (действительность токена и подтверждение, что это бот) и `getWebhookInfo` (отсутствие активного webhook, который конфликтует с long polling). Команда не вызывает `getUpdates`, `sendMessage` или `deleteWebhook`. Значение `check_error` содержит только заранее известные коды ошибок, никогда URL webhook, токен или тело ответа.

## Как интерпретировать вывод

- `token_configured=true`: локальный токен задан; не означает, что он работает.
- `telegram_identity_verified=true`: Telegram API подтвердил тестовую учётную запись бота.
- `webhook_inactive=true`: Telegram не сообщил об активном webhook.
- `polling_preflight_passed=true`: только идентификация и проверка webhook успешно пройдены, **это не проверка отправки сообщений и не разрешение на запуск**.
- `message_sent=false`: эта команда не отправляла сообщения.
- `public_release_approved=false`: всегда; публичный релиз требует отдельных проверок.

Если `webhook_active_polling_conflict`, **не удаляйте webhook автоматически**: сначала выясните, не обслуживает ли он существующий бот. При конфликте процессов не запускайте второй polling worker.

## Следующие шаги для контролируемого тестирования

1. Получить или выбрать отдельного тестового бота через @BotFather (не публиковать токен).
2. Выполнить сетевой read-only probe и подтвердить `polling_preflight_passed`.
3. Проверить шифрование, ключи, резервное копирование, удаление данных и офлайн-регрессии: `python -m app.services.offline_acceptance`.
4. Отдельно воспроизвести сценарий одного polling worker с тестовым аккаунтом, не включая экспериментальные исходящие операции. **Это следующий этап; текущая команда его не выполняет.**
5. До приглашения реальных пользователей провести независимые проверки содержания, конфиденциальности и безопасности.

**Границы:** бесплатное круглосуточное облако не развёрнуто; GitHub Actions — средство тестирования, а не сервер бота. Наличие токена и зелёного CI не означает, что пользовательский Telegram-бот реально доступен.
