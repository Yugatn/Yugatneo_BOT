# Архитектура научной базы знаний

## Цель
Короткий проверяемый индекс утверждений для Telegram-бота и будущих приложений. Каждый элемент содержит ID, тему, RU/EN, категорию доказательности, библиографический источник, ссылку, дату проверки и минимальный возраст.

Код: `app/services/knowledge_index.py`.

## Категории
- `guideline` — рекомендации организации; важно указывать область применения и дату.
- `research` — исследовательские результаты, требующие оценки качества.
- `theory` — теоретические модели, не равнозначные установленному универсальному закону.
- `author_hypothesis` — авторские идеи, не выдаваемые за научный консенсус.

## Правила для будущего ИИ
1. Выбирать записи только по теме и допустимой возрастной категории.
2. Не смешивать гипотезы с рекомендациями ВОЗ и исследованиями.
3. Указывать источник, уровень доказательности и ограничения при содержательном ответе.
4. При отсутствии подтверждения сообщать о неопределённости.
5. Не делать выводов о диагнозах, способностях или личности на основании одного ответа.
6. Не предоставлять философские авторские разделы несовершеннолетним; взрослым — только при добровольном выборе.
7. Отделить редакторское обновление знаний от генерации текста ИИ; любое изменение источника проходит проверку.

## Важное ограничение
Индекс содержит стартовые библиографические ссылки. Их наличие **не доказывает** корректность каждой формулировки и не означает проведённого систематического обзора. Перед закрытой бетой нужна научная редактура, проверка доступности первоисточников и юридическая/возрастная оценка по регионам.

## Дальнейшие шаги
Подключить безопасную выдачу этих записей в раздел «Психограмотность», создать независимые тесты корректности цитирования и контрольный набор вопросов. Подключение OpenAI делать только после валидации контекста и ограничения чувствительных данных.
