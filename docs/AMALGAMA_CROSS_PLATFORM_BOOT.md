# AMALGAMA — кроссплатформенная оболочка, Guardian и загрузка с USB

**Статус:** технический план, не готовый загрузочный образ и не инсталлятор.

## Доверие и криптографическая подпись

`amalgama/signed_manifest.py` проверяет Ed25519-подпись канонизированного JSON-манифеста. Открытый ключ передаётся из независимого доверенного источника. Манифест не исполняется; проверка подписи не подтверждает безопасность самого кода. Закрытые ключи должны храниться вне репозитория и вне рабочей среды агента. Для защиты от отката нужны монотонные версии и внешний доверенный счётчик, пока не реализованы.

## Независимый Guardian

`guardian_worker.py` выполняет однократную проверку подписанного манифеста и хешей агентов. **Это отдельный процесс, но не sandbox**. Для Linux следующим этапом нужен systemd unit с `PrivateNetwork=yes`, `NoNewPrivileges=yes`, `ProtectSystem=strict`, `ProtectHome=yes`, ограничением файловых путей, `DynamicUser=yes` и `SystemCallFilter` после тестирования совместимости. Для macOS нужен подписанный отдельный helper с sandbox и минимальными entitlements. Windows — restricted token / AppContainer с отдельной проверкой. Не обещать полной независимости от скомпрометированного ядра.

## Платформы

- macOS: пользовательский read-only прототип; системные события потребуют разрешённых API Apple.
- Linux: Python-прототип; будущие сенсоры fanotify/audit/eBPF/LSM и пакеты DEB/RPM.
- Windows: Python-прототип; будущие ETW/Defender/App Control.
- Никакая платформа не допускает несанкционированную установку или обход политики загрузки.

`amalgama/platform.py` только определяет возможности; не устанавливает системные службы.

## Live USB / UEFI

1. Пользователь **сам** записывает подписанный Live-образ на флешку.
2. Пользователь явно выбирает USB-устройство в UEFI Boot Menu; простая вставка флешки не запускает код.
3. Подписанный загрузчик и образ проходят Secure Boot, если это поддерживается и настроено.
4. AMALGAMA Live загружается без монтирования внутренних дисков на запись.
5. Только с согласия владельца проводится инвентаризация ОС и оборудования; личные файлы не читаются по умолчанию.
6. Предлагается выбор: только диагностика, установка user-space агента, подготовка пакета для Linux или выход.
7. Установка требует отдельного подтверждения, проверенного источника пакетов, прав ОС и возможности отката.
8. Ни один режим не форматирует диск и не меняет EFI/NVRAM/загрузчик без отдельного явного решения.

Для реализации Live USB использовать поддерживаемый Linux-дистрибутив и его стандартную инфраструктуру сборки и подписи. Не писать собственный загрузчик/UEFI-прошивку на первом этапе.

## Тесты и ограничения

Проверки: `python -m pytest tests/test_amalgama_signed_manifest.py`. Для криптографии требуется `cryptography`. CI и запуск на macOS/Linux/Windows ещё не подтверждены.

Безопасное восстановление: только отдельная рекомендация с подтверждением человека. Автоматическое копирование или исполнение доверенных образов пока отсутствует.
