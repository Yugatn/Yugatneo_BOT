# Диагностическое шифрование: этап 1

В диагностическом модуле реализовано **необязательное** аутентифицированное шифрование поля `diagnostic_sessions.answers_json` с помощью Fernet (cryptography). Если `YUGATNEO_DATA_ENCRYPTION_KEY` не задан, новые записи по-прежнему сохраняются открытым текстом для совместимости. **Это не шифрование всей базы и не полная защита данных бота.**

## Подключение
Сгенерируйте ключ на сервере: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`. Сохраните его в менеджере секретов хостинга как `YUGATNEO_DATA_ENCRYPTION_KEY`. Не записывайте ключ в GitHub, публичные документы или сообщения Telegram. Для работы необходима библиотека `cryptography`.

При настроенном ключе новые и обновлённые диагностические ответы шифруются перед сохранением. Старые незашифрованные записи читаются, но **не мигрируют автоматически**. Потеря ключа делает зашифрованные записи нечитаемыми; его нужно резервировать отдельно от базы с ограниченным доступом.

## Ограничения и дальнейшая работа
- Данные колеса баланса, профориентации, состояния Telegram и другие таблицы **ещё не шифруются**.
- Идентификаторы, индексы, временные метки и размеры записей остаются видимыми в SQLite.
- Шифрование не защищает данные в памяти работающего процесса или от владельца серверного ключа.
- Перед запуском с реальными данными нужны контролируемая миграция старых записей, ротация ключей, проверка бэкапов и процедуры восстановления.
- Для производственной среды рекомендуется обязательный ключ и отказ запуска при его отсутствии после завершения миграции.
- Для всех персональных данных нужны политика хранения, согласие пользователей, удаление из резервных копий и отдельный аудит внешних провайдеров.


## Режим запуска (добавлено)

Перед запуском Telegram polling вызывается проверка конфигурации. Установите `YUGATNEO_ENV=production` для производственного развёртывания. В этом режиме бот не запустится без корректного `YUGATNEO_DATA_ENCRYPTION_KEY`. В `development` и `test` ключ остаётся необязательным. **Это не означает, что все поля базы зашифрованы:** оценки колеса, история и другие таблицы требуют отдельной миграции и защиты.


## Миграция старых диагностических записей

Перед изменением базы остановите бот, создайте зашифрованную резервную копию и проверьте её восстановление. Установите правильный ключ через защищённые переменные окружения.

Проверка без изменений:

`python -m app.services.migrate_diagnostic_encryption --db /secure/path/diagnostic.sqlite3`

Применение после проверки:

`python -m app.services.migrate_diagnostic_encryption --db /secure/path/diagnostic.sqlite3 --apply`

Команда показывает только количество записей; повторный запуск пропускает уже зашифрованные строки. Миграция касается только `diagnostic_sessions.answers_json`; другие таблицы не мигрируют.
