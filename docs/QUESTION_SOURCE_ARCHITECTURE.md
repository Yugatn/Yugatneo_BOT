# Архитектура источников вопросов Yugatneo BOT

## Принцип
Бот — **гибридная система**: структурированный каталог утверждённых вопросов + конечный автомат сценария + необязательная генеративная модель. OpenAI не является хранилищем, единственным источником вопросов или гарантом методической достоверности.

## Реальное состояние
- В репозитории уже есть `data/questions.ru.json` версии 1.1.0: 310 вопросов с `id`, `category`, `subcategory`, `text`, `purpose`, `tags`, `risk_level`.
- `app/services/reflection_paths.py` содержит 3 стартовых сценария по мотивам КПТ, гештальт-подхода и коучинга. Интеграцию этих сценариев с Telegram-интерфейсом требуется проверить и завершить.
- Google Sheets пока не подключён. Таблица не должна быть единственным источником вопросов.
- Не обещать психотерапию или клинический результат; сценарии для самостоятельного исследования требуют редакторской и этической проверки.

## Три слоя
1. **Версионируемый нормативный каталог** — JSON в GitHub, проверенный при сборке; с приложением поставляется локальный snapshot. Это авторитетный набор опубликованных вопросов.
2. **Редакторский источник** — закрытая Google Таблица только для разработчика/редакторов. Необязательна; может содержать черновики и новые редакции. Перед публикацией требуется экспорт, проверка схемы, дубликатов, ограничений безопасности, редакторское одобрение и коммит в Git. В рантайме обращаться к Sheets не нужно.
3. **ИИ-сервис** — использует ограниченную подборку опубликованных вопросов и краткий, разрешённый пользователем контекст. Может переформулировать мягкие пояснения, но не должен назначать диагнозы, создавать платные ограничения для бесплатной помощи или заменять протокол безопасности.

## Поток выполнения
Telegram message
→ отдельный safety filter / consent gate
→ состояние сценария (SQLite: user_id, path, step, статус)
→ selector(question catalog + этап + запрос пользователя)
→ [LLM доступен и согласие есть?] → уточняющий ответ с опорой на вопрос
                                  или → шаблонный ответ / исходный вопрос
→ сообщение пользователю
→ запись минимального статуса шага.
Текст личных ответов не сохранять без явного согласия и понятного срока хранения.

## Правила выбора
- Идентификатор вопроса стабилен между редакциями; переиспользовать удалённые идентификаторы нельзя.
- У каждого вопроса: методическое семейство, направление/этап, тип действия, допустимый уровень напряжения, условия пропуска, версия, статус редакторской проверки.
- В сценарии строго поддерживать `/skip`, `/cancel` и право отказаться от вопроса.
- Важные изменения каталога публикуются только после валидации; заготовка в Sheets сама по себе не становится боевым вопросом.
- Если генеративная модель недоступна, продолжать сценарий офлайн-каталогом; если каталог невалиден — оставить безопасное информирующее меню, не угадывать вопросы.
- В состоянии повышенного риска стандартный коучинг уступает проверенным инструкциям помощи человеку, а не свободной генерации.
- Платная программа «Разобусловливание» — отдельный добровольный образовательный/рефлексивный трек, без гарантии «пробуждения». Бесплатные сценарии сохраняются.

## Таблица — рекомендуемые колонки
`id, version, status, access_tier, approach, category, subcategory, stage, text_ru, purpose, tags, risk_level, skip_allowed, source_reference, reviewer, reviewed_at`

`status`: draft / reviewed / published / retired.
`access_tier`: core / extended (не управляет экстренной помощью).
`source_reference` — ссылка на методическое описание или признак авторского вопроса.
Не хранить в этом листе Telegram ID, диагнозы, историю беседы, токены API или личные ответы.
