# Yugatneo BOT

Мультиплатформенный ИИ-помощник для коучинга, психологической рефлексии и психообразования.

> **Границы продукта.** Бот не ставит диагнозы, не заменяет психотерапевта или экстренную помощь и не обещает лечение. До запуска нужны клиническая/этическая проверка сценариев, политика конфиденциальности и проверка применимого законодательства.

## Цели

- Единое ядро диалога, не привязанное к конкретной языковой модели.
- Каталог коучинговых и рефлексивных вопросов с темами, тегами и подсказками по применению.
- Интерактивная не-клиническая анкета и адаптивная перенастройка порядка вопросов по теме, возрастной группе и добровольным самоописаниям.
- Предварительный кризисный предохранитель, который ставит безопасную передачу выше обычного ответа ИИ; он не является клиническим детектором.
- Все базовые функции и вопросы доступны бесплатно; Tribute — необязательная добровольная поддержка проекта.
- Адаптеры каналов: Telegram, Instagram Direct и WhatsApp. MAX — отдельный последующий адаптер после подтверждения доступа к официальному API.
- Безопасная замена провайдера модели: сейчас mock-движок, позднее OpenAI или другой совместимый провайдер.
- Сначала минимальный бюджет: локальная разработка и бесплатные квоты/тарифы там, где они доступны. Бесплатный круглосуточный хостинг и бесплатные запросы к модели не гарантируются.

## Статус

Это стартовый каркас с каталогом из **310 вопросов в 31 тематическом направлении**, с неограниченным бесплатным доступом, опциональными ссылками Tribute и тестами. Он не является уже запущенным ботом: для реальных сообщений понадобятся токены каналов, публичный HTTPS webhook, хранилище, выбранная модель и настройки оплаты. Платёжная интеграция пока не включена.

## Бесплатный доступ и добровольная поддержка

Все вопросы каталога и базовый диалог доступны без ограничения по количеству и без обязательной подписки. Настройки Tribute выключены по умолчанию. Когда владелец проекта создаст ссылку поддержки/доната или цифрового продукта в Tribute, её можно включить через переменные окружения. Оплата не открывает доступ к базовым вопросам и не является условием получения помощи.

- `TRIBUTE_ENABLED=false` — по умолчанию кнопка поддержки скрыта.
- `TRIBUTE_ENABLED=true` и `TRIBUTE_SUPPORT_URL=...` — показывать необязательную ссылку на поддержку.
- `TRIBUTE_PAID_PRODUCT_URL=...` — дополнительная ссылка на созданный в Tribute продукт, если она нужна.
- Ссылки создаются владельцем аккаунта в Tribute; приложение не принимает данные банковских карт и не считает платёж подтверждённым только по клику.
- Базовые функции и информация о кризисной помощи остаются бесплатными независимо от донатов.

Подробности: [docs/MONETIZATION.md](docs/MONETIZATION.md).

## Коучинговый API Колеса баланса (staging, выключен по умолчанию)

Ветка разработки содержит `/api/v1/miniapp/coaching`: короткоживущие серверные сессии с обязательным согласием, проверкой Telegram Mini App initData, изоляцией владельцев и без постоянного хранения текста ответов. Это **детерминированные вопросы**, не психотерапия и не генеративный ИИ-чат. Флаг `MINIAPP_COACHING_ENABLED=false` оставляет маршруты недоступными до проверки безопасности и приватности. См. [docs/MINIAPP_WHEEL_COACHING_API.md](docs/MINIAPP_WHEEL_COACHING_API.md).

## Быстрый старт

Требуется Python 3.11+.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --reload
```

Пока Telegram/Meta credentials не заданы, приложение запускается в режиме разработки и не принимает реальные сообщения платформ. Интерактивная диагностика и ограничения кризисной обработки: [docs/DIAGNOSTIC.md](docs/DIAGNOSTIC.md). Команды в диалоге: `диагностика`, `порядок вопросов`, `сбросить диагностику`. Подробности: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), [docs/SAFETY.md](docs/SAFETY.md), [docs/SECURITY.md](docs/SECURITY.md), [docs/DECONDITIONING.md](docs/DECONDITIONING.md), [docs/CHANNELS.md](docs/CHANNELS.md).

- `app/core/` — конфигурация, модели данных, правила доступа.

## Принципы

1. Не хранить токены в Git; использовать переменные окружения/секреты хостинга.
2. Не отправлять личные данные в модель без необходимости и информирования пользователя.
3. Не использовать один и тот же идентификатор пользователя между каналами без явного связывания аккаунтов.
4. Не выдавать предположения модели за диагнозы или достоверные факты.
5. Не запускать платежи и обработку чувствительных данных до проверки безопасности и правовых требований.

## Защита и разобуславливание

- Защитный каркас: лимиты запросов, ограничение размера payload, security headers и endpoint проверки Cloudflare Turnstile. Интеграция CAPTCHA с реальными каналами требует завершения webhook-адаптеров; см. [docs/SECURITY.md](docs/SECURITY.md).
- Библиотека расширена до 310 вопросов. Методика самоисследования обусловленности описана в [docs/DECONDITIONING.md](docs/DECONDITIONING.md). Это добровольная рефлексия, не «стирание личности» и не клиническая процедура.


## Проверка подключения Telegram (без сообщений и без затрат на ИИ)

Сначала убедись, что токен **тестового** бота от @BotFather сохранён только в локальном `.env`. Он не нужен для офлайн-тестов; для проверки Telegram API потребуется собственный тестовый токен.

```bash
python -m app.telegram_staging_probe
python -m app.telegram_staging_probe --online
```

Вторая команда выполняет **только** `getMe` и `getWebhookInfo`: проверяет, что Telegram узнаёт бота и что нет активного webhook, несовместимого с long polling. В отчёте только логические флаги и обезличенные коды ошибок: токен, webhook URL и содержимое сообщений не выводятся. `polling_preflight_passed=true` **не означает**, что бот уже работает круглосуточно или одобрен к выпуску.

Полная инструкция: [docs/TELEGRAM_STAGING_CONNECTIVITY.md](docs/TELEGRAM_STAGING_CONNECTIVITY.md). Синтетические офлайн-проверки: `python -m app.services.offline_acceptance`.

**Нынешний блокер публичного запуска:** нет подтверждённых реального Telegram staging-теста, постоянного хостинга, восстановления данных и независимых клинической/приватностной/безопасностной проверок. Предыдущий процент готовности — оценка разработки, а не доказательство доступности бота в Telegram.

## Telegram: локальный MVP

В репозитории есть минимальный long-polling запускатель Telegram: `app/telegram_polling.py`. Он использует существующий `TELEGRAM_BOT_TOKEN` из локального `.env`, не требует публичного HTTPS webhook для локального теста и хранит оценки колеса в локальной SQLite-базе.

Функции MVP:
- `/start` и меню;
- добавление собственных сфер колеса баланса и оценок 0–10;
- просмотр сохранённых оценок;
- диалоговая рефлексия через текущий провайдер модели;
- `/cancel` для выхода из сценария.

Запуск на MacBook из корня репозитория:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Затем открой локальный `.env` в редакторе и заполни `TELEGRAM_BOT_TOKEN` токеном от @BotFather. Не вставляй токен в чат, исходный код или GitHub. После сохранения файла запусти:

```bash
python -m app.telegram_polling
```

Остановить процесс: `Ctrl+C`. Пока процесс работает, бот отвечает; это локальный тест, не круглосуточный облачный запуск. Оценки хранятся в файле `yugatneo_bot.sqlite3` на этом компьютере. Перед реальным использованием нужно дополнительно проверить поведение безопасности, приватность, обработку ошибок и сценарии удаления данных.
