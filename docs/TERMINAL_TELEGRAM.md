# Telegram через терминал MacBook

## Два режима доступа

**Бот:** Telegram Bot API по HTTPS, без входа в личный аккаунт. Токен выдаёт @BotFather. Бот не может сам начать личный диалог с произвольным пользователем: сначала пользователь должен написать боту. Локальная проверка работает через long polling и не требует webhook.

**Личный аккаунт:** отдельный клиент Telegram (Telethon/TDLib) и авторизация через Telegram API ID/API Hash, номер, код входа и, если включена, двухэтапная проверка. Bot token не даёт доступ к личному аккаунту. Не отключайте двухэтапную защиту ради удобства. Наличие отдельного номера не отменяет правил авторизации и получения API-ключей.

## Первая проверка: одна команда за раз

В Terminal MacBook, в папке репозитория, выполните:

```bash
python3 --version
```

Ожидается `Python 3.11` или новее. Отправьте наставнику **только вывод этой команды**, без токенов и кодов. Наставник должен проверить результат и только затем предложить следующую команду.

Следующие этапы: `git --version`, клонирование репозитория, виртуальное окружение, установка зависимостей, локальный `.env`, запуск `python -m app.telegram_polling`, проверка `/start` в Telegram на телефоне.

## CLI для сообщений бота

После локальной настройки токена можно использовать `python -m app.telegram_cli me` для проверки подключения, `python -m app.telegram_cli updates` для просмотра доступных обновлений и `python -m app.telegram_cli send CHAT_ID "Тестовое сообщение"` для отправки в разрешённый чат. Токен не передаётся аргументом CLI и не должен появляться в истории команд. Не запускайте `updates` одновременно с long-polling процессом бота: Telegram не поддерживает конкурирующих потребителей `getUpdates`.

## Приватность

Терминал сам по себе **не гарантирует большей приватности**. Bot API не использует сквозное шифрование для общения с ботом. HTTPS защищает транспорт; владелец бота и инфраструктура Telegram могут обрабатывать сообщения. Не публикуйте `.env`, session-файлы, журналы переписки, номера и коды входа. Для психологического продукта отдельно нужны согласие, минимизация данных, политика хранения и удаление.
