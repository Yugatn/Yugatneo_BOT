# YUGATNEO AMALGAMA — концепция адаптивной защитной оболочки

Статус: архитектурная концепция, не действующий антивирус.

## Замысел

При первоначальной настройке формируется доверенная базовая линия: подписи и хеши критичных компонентов, политика доступа, доверенные источники обновлений, настройки безопасности и допустимые системные изменения. Это не копия ОС и не гарантия её абсолютной защищённости. Базовая линия обновляется только через проверяемые процедуры.

«Амальгама» — метафора многоуровневой защиты: системные политики предотвращают опасные действия, сенсоры наблюдают за событиями, а агенты анализируют аномалии и помогают локализовать инциденты.

## Уровни

1. **Trusted baseline:** подписи исполняемых файлов, состояние важных конфигураций, журнал доверенных изменений; первичную установку нельзя считать доверенной, если ОС уже скомпрометирована.
2. **Sensors:** события файловой системы, запуска процессов, изменения привилегий, доступа к защищённым ресурсам и сетевых соединений через поддерживаемые API ОС.
3. **Deterministic enforcement:** правила минимальных привилегий, sandbox, ограничения запуска и доступов. Блокировка критичных операций не зависит от задержек ИИ.
4. **AI analysis:** корреляция событий, объяснение подозрительных последовательностей, приоритизация расследования, предложения по изоляции. Модель не получает неограниченные системные права.
5. **Response:** журналирование, уведомление, отзыв разрешений, остановка или изоляция процесса, безопасное восстановление из проверенной резервной копии; разрушительные операции требуют подтверждения и возможности отката.
6. **Recovery:** проверка целостности, восстановление доверенной версии, фиксация причин инцидента и проверка после перезагрузки.

## Модель событий

`SecurityEvent`: id, timestamp, host_id, process_id, actor, action, resource, source, evidence_hash, severity, confidence.

`Incident`: id, related_event_ids, status, analyst_summary, proposed_action, user_decision, resolution.

`BaselineVersion`: id, created_at, trusted_source, policy_digest, signature, supersedes_id.

Все выводы ИИ отделяются от наблюдаемых событий. Метки: OBSERVED, DERIVED, CLAIMED, NOT_TESTED, CONFLICTED, Residual.

## Политика агентов

- Агент целостности сравнивает события с доверенной базовой линией.
- Агент процессов выявляет необычные цепочки запуска и эскалацию привилегий.
- Сетевой агент анализирует метаданные соединений; содержимое переписки не собирается по умолчанию.
- Агент расследования связывает события и объясняет неопределённость.
- Агент реагирования предлагает действие; опасные операции проходят отдельный проверяемый механизм авторизации.

Агенты не должны бесконтрольно удалять файлы, блокировать ОС или отправлять личные данные в облако. Предпочтение — локальной обработке, минимизации данных и явному согласию на облачный анализ.

## Реалистичные платформенные механизмы

- **macOS:** Endpoint Security Framework (с соответствующими entitlement), System Extensions, notarization, XProtect и встроенные механизмы защиты.
- **Windows:** Windows Defender, ETW, App Control for Business, ограниченные сервисы и поддерживаемые интерфейсы фильтрации.
- **Linux:** fanotify, audit, eBPF/LSM при доступности и надлежащих привилегиях.

Не пытаться обходить защиту ядра или отключать встроенный антивирус.

## Ограничения и угрозы

Невозможно обещать обнаружение всех вторжений. Вредоносное ПО с правами ядра, компрометация загрузки, атаки на прошивку и вмешательство в сенсоры могут сделать наблюдение неполным. Изменение файла не всегда является атакой: обновления, установка приложений и действия пользователя легитимны. Требуются ложноположительные/ложноотрицательные метрики, тесты производительности и безопасный режим восстановления.

## MVP

1. Выбрать одну платформу, предпочтительно macOS для первого прототипа.
2. Реализовать read-only сбор разрешённых системных событий без драйвера ядра.
3. Построить подписанную базовую линию для ограниченного набора директорий и политик.
4. Создать журнал событий и детерминированный коррелятор.
5. Подключить ИИ только для объяснения событий и предложения действий.
6. Протестировать на безопасных синтетических сценариях; измерить задержку, нагрузку, ложные срабатывания.
7. Лишь после тестирования добавить обратимые защитные действия.

## Связь с YUGATNEO

AMALGAMA может в будущем обеспечивать безопасность Messenger и Symbiot через отдельный локальный агент и API событий. Данные коучинга и переписки не должны становиться доступными антивирусному анализатору без отдельного основания и согласия. У компонентов разные права доступа и ключи.

## Критерий готовности

Концепция считается реализованной только после проверенного прототипа, воспроизводимых тестов и аудита безопасности. Этот документ — техническое задание, а не подтверждение защитных свойств.
