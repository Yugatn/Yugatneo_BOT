# Диагностика для выбора порядка вопросов

## Назначение

Модуль `app/services/diagnostic.py` формирует предварительный порядок вопросов из каталога. Это короткая навигационная анкета, а не клиническая диагностика, не психометрический тест и не доказательство психотипа.

API: `POST /diagnostic/recommend`. Запрос содержит возраст, необязательное самоописание гендера, самоописание темперамента и психотипа, тему запроса, субъективную интенсивность дистресса, срочность и предпочтительный стиль диалога. Ответ возвращает первые тематические категории, отложенные категории и список вопросов. Эндпоинт не сохраняет профиль в базе данных.

## Поля и правила использования

- **Возраст** — используется только для возрастной настройки порядка. Для пользователей младше 18 лет порядок начинается с конкретных и поддерживающих тем; возраст не считается показателем зрелости.
- **Гендер** — необязательное самоописание. Не влияет на психологические оценки и не используется для гендерных стереотипов. Позднее можно применять только для выбранного пользователем языка и контекста.
- **Темперамент** — пользователь сам выбирает одно из условных описаний (сангвинический, холерический, флегматический, меланхолический) либо «не уверен». Это не диагноз и не надёжная научная типология личности. Поле лишь слегка влияет на порядок тем и темп беседы.
- **Психотип** — свободное самоописание, например «аналитический» или «ориентированный на действие». Сервис не выводит тип автоматически и не присваивает ярлыки.
- **Тема** — определяет релевантные категории каталога.
- **Дистресс (0–4)** — субъективная оценка пользователем, а не шкала тяжести заболевания. При высоком значении первыми идут ресурсы, повседневная устойчивость, стресс и эмоции.
- **Срочность** — отражает предпочтение пользователя по времени, не является оценкой риска.
- **Стиль** — структурированный, открытый, прямой или бережный; меняет последовательность, а не оценку человека.

## Принципы очередности

1. Сначала — контакт с текущей ситуацией, ресурсы и стабилизация, если пользователь сообщает о сильном напряжении.
2. Затем — вопросы по заявленной теме.
3. Далее — убеждения, автоматические сценарии, обусловленность и идентичность, если это соответствует запросу.
4. Более глубокие темы не навязываются; пользователь может пропустить вопрос или поменять тему.
5. Вопросы о травматическом опыте не должны появляться как обязательный первый шаг. Перед ними требуется отдельное согласие, готовность пользователя и безопасный сценарий; текущий модуль не является разрешением автоматически исследовать травму.

## Пример запроса

```json
{
  "age": 34,
  "gender": "не указывать",
  "temperament": "unsure",
  "psychotype": "аналитический (самоописание)",
  "goal": "conditioning",
  "distress": 2,
  "urgency": "normal",
  "style": "structured",
  "limit": 12
}
```

Допустимые значения темперамента: `sanguine`, `choleric`, `phlegmatic`, `melancholic`, `unsure`. Стиль: `structured`, `open`, `direct`, `gentle`, `unsure`. Темы: `emotions`, `anxiety`, `relationships`, `goals`, `identity`, `conditioning`, `work`, `general`.

## Ограничения и безопасность

- Не называть результат «диагнозом» и не сообщать человеку, что он «такой-то тип».
- Не делать выводы о риске, диагнозе или пригодности терапии по возрасту, гендеру, темпераменту или одному ответу.
- Если пользователь сообщает о непосредственной опасности или риске причинить вред себе/другим, приоритет — живой специалист и местная экстренная помощь; обычная последовательность вопросов прекращается.
- Возраст, гендер и психологические самоописания — чувствительный контекст. Сейчас endpoint их не сохраняет; перед будущей аналитикой нужно отдельное согласие, минимизация данных и срок хранения.
- Логика эвристическая и требует оценки специалистом по психотерапии/психологии, тестирования с разными группами и последующей корректировки по добровольной обратной связи.
