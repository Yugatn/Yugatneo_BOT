# AMALGAMA — реестр доверенных агентов и план восстановления

Ветка развивает архитектуру YUGATNEO METALITENT: отдельный Guardian может сверять исполняемые файлы агентов с независимым реестром, а Recovery Manager только **предлагает** восстановление.

## Границы прототипа

- Реестр JSON версии 1, его SHA-256 должен быть известен оператору из отдельного доверенного источника.
- Агентам в реестре разрешён только пустой список привилегий.
- Проверяются ID, относительные пути, хеши и отсутствие дубликатов.
- Подмена реестра, изменение агента, отсутствие агента и выход за пределы разрешённого каталога приводят к отказу либо сигналу.
- Recovery Manager не запускает процессы, не удаляет файлы, не копирует исполняемые компоненты и не повышает привилегии.
- Восстановление доверия к скомпрометированной ОС изнутри этой же ОС не гарантируется.

## Пример реестра

```json
{"schema":1,"agents":[{"id":"watcher","path":"agents/watcher.py","sha256":"<64 lowercase hex digits>","permissions":[]}]}
```

Пример использует заглушку вместо настоящего хеша; для реальной проверки вычислить SHA-256 конкретного файла и независимо закрепить SHA-256 итогового реестра.

## Следующая итерация

Подписи Ed25519 и проверка цепочки доверия; изолированный процесс Guardian; защита от подмены файлов во время проверки; безопасный стенд восстановления из доверенного подписанного артефакта; независимые тесты на macOS. До этого автоматическое восстановление и создание новых агентов **запрещены**.

Проверки: `python3 -m pytest tests/test_amalgama_registry_recovery.py`.
