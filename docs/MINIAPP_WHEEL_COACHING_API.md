# Telegram Mini App — коучинговый API по Колесу баланса

**Статус: STAGING / DISABLED BY DEFAULT. Не готов для публичного или клинического применения.**
Дата: 2026-10-31. Основа: `main` `f88e63fead7fae9f734970a8904b80a0d69e0534`.

## Цель и границы

Это первый защищённый транспортный контур для добровольной рефлексии после оценки луча. Реализован **не ИИ-чат**, а серверный конечный автомат с подготовленными открытыми вопросами. Все ответы обрабатываются в рамках одного HTTP-вызова без записи текста в SQLite, без передачи LLM и без формулирования диагноза. «Психотерапия» в названии API отсутствует намеренно.

Код на клиенте PSY-TOOLS `wheel/coach.html` (черновик PR #6) пока самостоятельный офлайн-коуч: он не посылает никаких запросов этому API. **Автоматического соединения двух систем нет.** Подключение допускается только после отдельной проверки согласия, origin policy, пользователя и конфиденциальности.

## Операции

Префикс `/api/v1/miniapp/coaching`.

- `POST /sessions`: создать сессию. Требует Telegram Mini App подпись через заголовок `Authorization: tma <initData>` и одновременно `consent_for_server_processing: true`, `adult_attested: true`; принимает `wheel_id`, `ray_id` (только индекс вида `r0`, сверяемый с числом лучей), опциональный `score` (0–10 либо null), `mode` (`reflection`, `reframe`, `coaching`). Подпись и возраст `auth_date` проверяются на сервере; `user_id` из тела не принимается. В пилоте разрешены только обобщённые колёса `main, work, finance, relationships, social, development, rest, creativity, self_awareness`.
- `GET /sessions/{id}`: вернуть текущий вопрос и индекс хода **только владельцу**.
- `POST /sessions/{id}/turns`: `{expected_step,action,text?}`. `action`: `answer`, `skip`, `stop`. Обязательный индекс позволяет отклонить повторное продвижение с HTTP 409. Ответ пользователя не возвращается, не записывается в состояние и не пересылается провайдеру ИИ. При известных ключевых сигналах кризиса обычный сценарий немедленно завершается с предложением человеческой помощи.
- `DELETE /sessions/{id}`: удалить сессию своего аккаунта.
- `DELETE /sessions`: удалить все активные сессии текущего аутентифицированного аккаунта.

Сценарий содержит 5–6 вопросов. После последнего ответа состояние удаляется и возвращается `finished:true`; итог и оценки на сервер автоматически не сохраняются.

**Источник балла:** `wheel_id`, `ray_id`, `score` на этом этапе — данные добровольного самоотчёта из текущего запроса. Сервер **не удостоверяет**, что они соответствуют записям в личной истории `wheel_snapshots`, и не считает их клиническими показателями. Никакая оценка не переносится из локального `localStorage` без прямого действия пользователя.

## Модель безопасности и приватность

- **Выключено по умолчанию**: `MINIAPP_COACHING_ENABLED=false`. До отдельного решения и проверок включение не рекомендовано.
- **Вторая независимая блокировка**: API доступен только в явно указанных средах `development`, `test`, `staging`; любые иные значения `APP_ENV`, включая production и неизвестные алиасы, возвращают HTTP 503 **даже если флаг по ошибке включили**. Для будущего запуска потребуется отдельное изменение политики, код-ревью и повторная проверка безопасности.
- Только Telegram initData с корректной HMAC подписью; никакой доверенной клиентской `user_id`. Каждый GET/POST/DELETE заново проверяет подпись.
- Случайный идентификатор сессии `secrets.token_urlsafe(24)` (192 бит энтропии), проверка владельца, одинаковый 404 для отсутствующей и чужой сессии. Безопасность не основана только на секретности URL.
- Сессии только в памяти Python-процесса, TTL 20 минут; максимум две активные сессии на одного субъекта, 256 в одном процессе. По окончании/остановке/кризисной передаче удаляются.
- Приём отдельных сообщений ограничен 2000 символами и учётной частотой; HTTP-мидлварь уже ограничивает размер запросов.
- Собственно текст ответа не сохраняется ни в словаре состояния, ни в базе и не входит в HTTP-ответ. Это **не доказательство полного отсутствия технических копий** в прокси, логах или инфраструктуре — необходима проверка обработки данных во всём стеке.
- Транспорт поддерживает **строгий CORS allowlist** только для маршрутов `/api/v1/miniapp/coaching`. Переменная `MINIAPP_COACHING_ALLOWED_ORIGINS` (точные HTTPS origins, разделённые запятой) пуста по умолчанию; любые `*`, HTTP, URL с путями и некорректные записи приводят к запрету браузерного доступа. Заголовки `Authorization, Content-Type`, методы `GET, POST, DELETE`, no credentials; чужой `Origin` получает HTTP 403. CORS — не аутентификация и не защищает от скомпрометированных скриптов разрешённого origin.
- Только публичные координаты `r0...r8` для базового колеса и `r0...r7` для остальных разрешённых колёс. Произвольные `ray_id` с персональным текстом и чужие/неподходящие индексы отклоняются. Балл — самоотчёт, не валидированная история.
- Самоподтверждение совершеннолетия `adult_attested` **не является верификацией возраста**. Поэтому система остаётся staging-only и не даёт оснований для публичного запуска чувствительных сценариев.
- Колёса страхов, сексуальности, деструктивности и глубоких вложенных деталей пока исключены из удалённого пилота; локальный офлайн-сценарий PSY-TOOLS остаётся отдельным.
- Ключевой обработчик `classify_crisis_message` — только предварительная эвристика, **не клинический детектор**. Его успешный тест не исключает пропущенных кризисов. Не подключать произвольные небезопасные генеративные ответы.

## Как тестировать без секретов

```bash
python -m pip install -r requirements.txt
python -m pytest -q tests/test_miniapp_coaching.py tests/test_telegram_miniapp_auth.py tests/test_wheel_snapshot_store.py
```

Тесты включают проверки согласия, двух субъектов, HMAC, срока сессии, ограниченного CORS и отказа в произвольном тексте `ray_id`. Они используют искусственные Telegram HMAC подписи и не запрашивают настоящие BotFather токены или OpenAI. Валидация выполняется только на CI/staging; **нет подтверждённого публичного развёртывания**.

## Отдельный интерфейс Mini App

Статический клиент `wheel/miniapp-coach.html` реализован в ветке PSY-TOOLS PR #6. Он не связан с реальным сервером по умолчанию: `miniapp-coach-config.js` устанавливает `apiOrigin: ""`. Telegram SDK подгружается **только по нажатию**; баллы читаются из локального браузера только по отдельному запросу; сетевой POST требует двух добровольных подтверждений. Chromium-тест использует подставной Telegram SDK и имитацию сервера, а не реальные подписи.

Реальное подключение требует независимого HTTPS staging origin, отдельного домена под Mini App (общий origin GitHub Pages не предназначен для чувствительных данных), строгого CSP `connect-src`, реального Telegram staging, внешнего ревью и последующей проверки юридических обязанностей. См. `wheel/TELEGRAM_MINIAPP_STAGING.md` в PSY-TOOLS PR #6.

## Следующие условия перехода к ИИ

1. Независимая проверка сценариев безопасности, приватности, возрастных требований и юридических оснований обработки информации.
2. Отдельный надёжный веб-логин **или** реальный Telegram Mini App с проверенным origin. Не использовать GitHub Pages `localStorage` как аккаунт.
3. Прозрачный отдельный opt-in на передачу именно текущего сообщения и минимального контекста провайдеру модели. Не отправлять весь профиль или журнал.
4. Секреты LLM только на сервере; жёсткие квоты бюджета, ограничение токенов, контроль инструкции/вывода, безопасный fallback.
5. Отдельная проверка результатов и кризисного маршрута на реальных устройствах с человеком и планом остановки.
6. Для production нескольких воркеров нужен общий TTL store с атомарным переходом состояния (и политикой удаления); текущее in-memory хранилище нельзя выдавать за устойчивое.

**Философский инвариант:** балл — контекстная модель оценки субъекта, а не характеристика личности. Субъект всегда вправе не отвечать, не менять ничего, остановиться и удалить текущую сессию. Совпадение ответа ИИ с авторской концепцией не является доказательством его истинности.
