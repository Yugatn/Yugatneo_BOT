# UX/UI v2 — единая модель Yugatneo BOT

Дата: 2026-10-23. Статус: спецификация, не утверждение о реализованном интерфейсе.

## Проверка концепт-макета
1. На изображении смешаны Telegram-чат, Telegram Mini App и мобильное приложение; следует разделить их на платформенные состояния, использующие одно API.
2. Визуализация 7 экранов — концепт, а не подтверждение наличия функций в коде.
3. На макете есть опечатки и мелкие подписи. В production-UI все тексты должны быть редактируемыми локализованными строками, не частью картинки.
4. Колесо и динамика требуют сохранения датированных оценок и версий состава лучей. Нельзя вычислять исторические изменения только по текущему состоянию.
5. ИИ-коучинг не должен интерпретировать оценку как диагноз или выдавать неподтверждённые факты о пользователе.

## Навигация
Общая схема: Главная → Колесо → Луч → Оценка → Результаты → Рефлексия. Отдельно: История, Профиль, Приватность.
Telegram chat: команды /start, /wheel, /coach, /history, /cancel; кнопки с короткими текстами.
Mini App: нижняя навигация «Главная / Колесо / Коучинг / История / Профиль».
iOS/Android: та же семантика экранов, системные компоненты, доступность и офлайн-очередь при отдельной реализации.

## Данные и API (проект)
- WheelDefinition: id, owner_id, version, title, rays[]; Ray: id, title, order, optional parent_id, active.
- Assessment: id, owner_id, wheel_version, created_at, answers[{ray_id, score 0..10, note?}].
- Reflection: id, owner_id, date, actions[], self_reported_mood?, income_progress?, creative_progress?, patterns_as_hypotheses[], next_step?.
- GET /api/v1/wheels, POST /api/v1/wheels, POST /api/v1/assessments, GET /api/v1/assessments, POST /api/v1/reflections, GET /api/v1/reflections.
- Все запросы аутентифицированы по каналу; Telegram initData валидируется на сервере; клиентский user_id не считается доказательством личности.
- Удаление и экспорт данных, согласие на обработку, минимизация хранения, сроки удаления — обязательны до публичного запуска.

## UX-проверки
- Пустое колесо; стандартные 9 лучей; пользовательские лучи; вложенные лучи; пропущенный ответ; повторная оценка.
- Смена версии лучей не ломает историю; сравнение только сопоставимых оценок.
- Ошибка сети; повторное нажатие «Сохранить» (идемпотентность); конфликт одновременного редактирования.
- Voice session: только добровольное включение пользователем; отчёт различает действия, самоотчёт и гипотезы.
- Доступность: крупные touch-targets, экранный диктор, контраст, отсутствие зависимости только от цвета.
- Безопасность: никаких диагнозов, давления, обязательных рекомендаций или автоматических решений за пользователя.

## Реализация по очереди
P0: проверить текущие обработчики и тесты, закрепить схему данных и миграции.
P1: единое API и Telegram Mini App с настоящими состояниями экранов.
P2: история и отчёты с проверяемым происхождением полей.
P3: мобильные клиенты на общем API.

## Статус
Документ — проектная спецификация. Эндпоинты, миграции и UI не считаются реализованными, пока нет кода и проходящих тестов.
