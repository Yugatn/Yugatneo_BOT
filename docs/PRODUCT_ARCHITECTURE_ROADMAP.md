# Yugatneo BOT — архитектура, UX, безопасность и дорожная карта

Статус: проектирование и реализация Telegram MVP. **Не является клинически валидированной психотерапевтической системой.** Публичный запуск отложен до отдельного этапа испытаний. Проценты ниже — экспертные оценки, не результат независимого аудита.

## 1. Архитектура продукта

**Каналы:** Telegram (первый MVP), далее единый API для web/PWA, iOS, Android, desktop. Бизнес-логика и данные не должны зависеть от Telegram-кнопок.

**Слои:**
1. Transport: Telegram Bot API (polling для разработки, webhook для устойчивого развёртывания, но никогда одновременно).
2. Navigation/state machine: главное меню, активная сессия, переход назад, продолжение, отмена, язык и возрастной профиль.
3. Domain: колесо баланса, коучинг, вопросы, профориентация/навыки, психообразование, родительство, отчёты.
4. Knowledge: версионированный каталог проверяемых утверждений, источники, дата проверки, уровень доказательности, региональная применимость.
5. AI orchestration: классификация намерения → выбор модуля → выбор разрешённого контекста → запрос к модели → валидация ответа → Telegram delivery.
6. Storage: раздельные публичные знания и персональные данные; шифрование, удаление, retention, резервное копирование.
7. Observability: технические метрики без содержания диалогов, оповещения, ограничение затрат, аудит релизов.

## 2. Предлагаемое главное меню

На первом экране не более шести смысловых пунктов (вместо текущих 15+ кнопок):
- 🧭 Колесо баланса — оценить сферы, сравнить историю, выбрать следующий шаг.
- 💬 Коучинг и рефлексия — свободный вопрос, КПТ-навыки, гештальт-рефлексия, ACT, ДБТ-навыки, мотивационное интервьюирование.
- 🎓 Профориентация и навыки — интересы, практические навыки, образовательные траектории, мини-эксперименты.
- 📚 Психологическая грамотность — развитие детей, родительство, когнитивная безопасность, творчество, ненасильственное общение.
- 📄 Мои результаты — краткий итог, подробный отчёт, история, экспорт, удаление.
- ⚙️ Настройки и безопасность — язык RU/EN, возрастные ограничения, приватность, помощь, согласия.

В каждом подменю: «◀️ Назад», «🏠 Главное меню», «⏹ Завершить». Первое посещение: выбор языка → краткое объяснение границ бота и хранения данных → добровольное согласие → возрастная категория → главное меню. Не требовать раскрытия точной даты рождения, диагноза или адреса.

## 3. Логика вопросов и ответов

### Сценарий колеса баланса
Выбор сферы → вопрос «насколько удовлетворён этой сферой от 0 до 10?» → необязательный вопрос «почему такая оценка?» → что уже помогает → маленький выполнимый шаг → подтверждение сохранения → отчёт. Девять базовых сфер плюс дополнительные по желанию. Не выдавать оценку как диагноз.

### Сценарий коучинга
Цель пользователя → выбор подхода → 1 вопрос за ход → короткое отражение ответа без приписывания скрытых мотивов → уточнение → выбор действия. В любой момент можно пропустить вопрос, сменить подход, завершить сессию или удалить данные. Для КПТ отделять ситуацию, мысль, эмоцию, поведение и альтернативные объяснения. Для гештальт-рефлексии не выдавать технику за клиническую терапию.

### Сценарий профориентации
Интересы → что уже пробовал → что получается → что хочется изучить → доступные условия → 2–3 гипотезы направлений → безопасный практический эксперимент → пересмотр гипотез. Для подростков — исследовательский, а не предписывающий формат. Не обещать достоверного определения профессии по короткому тесту.

### Опросники
Банк вопросов хранит `question_id`, `module`, `age_policy`, `locale`, `prompt`, `answer_type`, `required`, `skip_allowed`, `evidence_ref`, `version`, `risk_level`. Каждый вопрос должен иметь понятную цель, возрастную допустимость, локализацию, нейтральную формулировку и тест корректного перехода. Существующий каталог — источник для пилота, а не доказательство психометрической валидности.

### Ответ AI
1. Различить информационный запрос, самоисследование, запрос на действие и кризисный сигнал.
2. Проверить возрастные ограничения и согласие на чувствительные темы.
3. Извлечь только релевантные факты из базы знаний, не подмешивать данные других пользователей.
4. Не выдавать непроверенные утверждения за научный факт; отделять мнение, гипотезу, рекомендации и доказательства.
5. Проверить на выдуманные источники, диагнозы, опасные инструкции, навязанные интерпретации, неподходящую возрасту тему.
6. Выдать краткий ответ + максимум один следующий вопрос; предложить подробности по запросу.
7. Не публиковать личные ответы в Telegraph и не отправлять их в групповые чаты.

## 4. Информационная безопасность — модель угроз

**Активы:** Telegram bot token, ключи OpenAI и шифрования, ответы пользователей, отчёты, история, сервер и бэкапы.

**Угрозы:** кража токена; SQL-инъекции; спам/дорогие AI-вызовы; prompt injection; обход возрастных ограничений; доступ к SQLite и резервным копиям; повторная обработка Telegram updates; подмена публичной базы знаний; утечки в логах; компрометация зависимостей; ошибочное удаление чужих данных.

**Обязательные меры до закрытой беты:**
- секреты только в защищённом хранилище; разные ключи для dev/staging/prod, регулярная ротация;
- минимальные привилегии процесса, firewall, закрытая БД, TLS для webhook, проверка подлинности Telegram webhook secret;
- квоты на пользователя, глобальный лимит запросов и бюджета OpenAI, защита от повторов и контроль размера контекста;
- шифрование **всех** чувствительных записей и бэкапов, план миграции и проверка восстановления;
- ограничение хранения данных, экспорт и удаление, включая жизненный цикл резервных копий;
- dependency scanning, secret scanning, CI, code review и негативные тесты;
- отдельная политика обработки персональных данных с учётом юрисдикций, возраста и поставщиков AI.

## 5. Этапы релиза и критерии допуска

| Этап | Работы | Критерий завершения |
|---|---|---|
| A. Стабилизация | Все тесты, навигация, корректная обработка ошибок | CI зелёный на поддерживаемых версиях Python |
| B. Приватность | Шифрование, миграции, удаление, бэкапы | Тесты восстановления, независимая проверка доступа |
| C. Мозг бота | Каталог вопросов, state machine, контекст, правила качества ответов | Проверка сценариев на RU/EN и возрастных профилях |
| D. Инфраструктура | Staging, конфигурация, мониторинг, расходы | Повторяемое развёртывание без ручной правки секретов |
| E. Закрытое тестирование | Небольшая добровольная группа, UX, ошибки, red-team | Нет критических дефектов и утечек; есть план реагирования |
| F. Публичная бета | Постепенное расширение нагрузки | Стабильность, поддержка, мониторинг и возможность остановки |

**Пентест и проверка живого сервера выполняются на этапе E после развёртывания в staging и только на контролируемой инфраструктуре.** Сейчас применяются безопасные офлайн-тесты.

## 6. Оценка зрелости по направлениям (23 октября 2026)

| Направление | Оценка | Основание |
|---|---:|---|
| Telegram-функции и диалоги | 75% | Модули и команды есть, UX перегружен, нет живой проверки |
| Колесо баланса и отчёты | 80% | Хранение, история, действия, отчёты; нужны UX и полный аудит данных |
| Коучинг и подходы | 60% | Базовые вопросы есть, структурированные многоходовые сценарии ограничены |
| Профориентация и навыки | 65% | Рефлексия и отчёт есть; оценка компетенций и траектории требуют развития |
| Родительство и психообразование | 65% | Материалы есть; необходима редактура и научная верификация |
| RU/EN и доступность | 60% | Переключение реализовано частично; требуется полная локализация |
| Архитектура для отдельного приложения | 45% | API-основа есть, контракт каналонезависимого клиента не завершён |
| Инфраструктура/DevOps | 40% | CI есть, production/staging не подтверждены |
| Безопасность и конфиденциальность | 50% | Защитные тесты и частичное шифрование есть; полного аудита нет |
| Качество AI-ответов | 35% | Нужны реальные интеграционные проверки, источники и evaluation set |
| Тестирование и релизная готовность | 50% | CI есть, реальный Telegram, нагрузка, восстановление не проверены |

**Итоговая оценка готовности к контролируемой закрытой бете: около 55%.** Это взвешенная проектная оценка, а не арифметическое доказательство качества. Ранее упоминавшиеся 94% отражали завершённость узкого функционального прототипа и не учитывали полноценную эксплуатацию и безопасность.

## 7. Приоритеты следующего цикла

1. Исправить все CI-сбои, не повышать процент до зелёного CI.
2. Свернуть меню в шесть разделов без потери существующих команд.
3. Описать и протестировать state machine, возврат/отмену и согласие.
4. Создать versioned question bank и evaluation set: фактическая точность, нейтральность, безопасность, RU/EN.
5. Довести шифрование/миграцию до всех чувствительных таблиц.
6. Подготовить staging и план ограниченного запуска, без преждевременного публичного доступа.
